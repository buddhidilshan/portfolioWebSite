“Help everyone with everything” is a difficult brief to build or evaluate. A narrower job makes it easier to decide whether an agent is useful.

Start by naming the audience, the question or task, and the outcome they need. These planning principles apply to a Copilot agent without depending on a particular feature or configuration.

## Write the boundary first

Describe both the work the agent should handle and the point where a person should take over. For example, helping someone locate a procedure is a different responsibility from approving an exception to that procedure.

Decide which actions require confirmation and which decisions remain with an accountable person.

## Review the source material

An agent project is also a content project. Check whether the source material has an owner, a review date and a clear audience.

Look for contradictory instructions, obsolete procedures and unexplained abbreviations. If two documents disagree, resolve the disagreement instead of expecting the agent to make a policy decision.

## Make uncertainty useful

Plan what a helpful response looks like when the available information is incomplete. It might ask a focused question, point to a relevant source or explain how to reach the right person.

A confident answer is not automatically a useful answer. Readers need enough context to judge whether it applies to their situation.

## Build a small evaluation set

Collect representative questions before the first demonstration. Include ordinary requests, ambiguous wording, missing context and questions outside the intended scope.

For each example, describe what an acceptable response should do. Revisit those examples after changing instructions or source material.

## Design the handoff

A handoff should carry the context the person needs without exposing information unnecessarily. Tell the user what will happen next and avoid promising a response time that the support process cannot meet.

A well-bounded agent can still be valuable. It should make a particular job easier and make its limits understandable.
